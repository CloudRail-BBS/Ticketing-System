# Discourse 内置图标名快照 —— SvgSprite::SVG_ICONS 的一份拷贝。
#
# 用途：scripts/validate.py 用它校验「插件交给**核心**渲染的图标名」是否真的能
# 渲染出来。
#
# 为什么需要这个文件：核心的 `d-icon` 遇到不在精灵里的名字不报错、不警告，只是
# 什么都不画。侧边栏那一行于是看起来像「忘了配图标」，通知条目空一块，而真正的
# 原因是那个名字压根没被打包进精灵 —— 没有日志、没有异常，只有一块空白。
#
# 背景：Discourse 下发的精灵是 FontAwesome 的一个**子集**。`SvgSprite.bundle`
# 只打包 `SvgSprite.all_icons` 里的图标，而
#
#     all_icons = SVG_ICONS（本文件）+ 站点设置 / 主题 / 插件贡献的名字
#
# `core_svgs` 本身是 `vendor/assets/svg-icons/**/*.svg` 的全量解析（所以
# FontAwesome 有的它都有），但 `bundle` 那一步是
# `core_svgs.slice(*all_icons)` —— 不在 all_icons 里的名字拿不到。
#
# 两条出路，下面的检查都接受：
#
#   1. 名字在本清单里 —— 直接用。
#   2. 名字不在清单里 —— 在 plugin.rb 里 `register_svg_icon "名字"`，把它加进
#      插件贡献。核心自己的插件就是这么做的：discourse-cakeday 为自己的
#      `addCommunitySectionLink({ icon: "cake-candles" })` 调了
#      `register_svg_icon "cake-candles"`。
#
# 真实案例：`ticket`。FontAwesome 源文件里有它，SVG_ICONS 没有（本清单里 `ti`
# 开头只有 `tippy-rounded-arrow` 和 `title`）。侧边栏链接和通知条目都用它，于是
# 两处各自空了一块，控制台一片干净。现在 plugin.rb 里有 `register_svg_icon "ticket"`。
#
# 刷新方式（Discourse 加了新图标而你要用的时候）：
#
#   curl -sS https://raw.githubusercontent.com/discourse/discourse/main/lib/svg_sprite.rb \
#     | awk '/SVG_ICONS =/{f=1} f&&/^[[:space:]]*%w\[$/{g=1;next} g&&/^[[:space:]]*\],$/{exit} g{print}' \
#     | sed 's/^ *//;s/ *$//' | grep -v '^$' | sort -u
#
# 把输出替换掉本文件 `# ---` 以下的内容即可。
#
# 注意它是一份**快照**：比你的 Discourse 新的时候，你会看到一个其实可用的名字被
# 判为错误。那时先跑上面的命令刷新，再判断是不是真的写错了。
